Protocole VPIV

Format unique de communication entre tous les sous-systèmes RobotRZ. Transporté par MQTT. Partagé et compris identiquement par SP, SE et Arduino.

Format canonique
$ CAT : VAR : PROP : INST : VAL #
CAT
V I E F A
position 0
VAR
CfgS Sys Gyro…
position 1
PROP
modeRZ dataCont…
position 2
INST
* SE rear…
position 3
VAL
valeur
position 4
⚠ PROP est en position 2, INST en position 3 — erreur récurrente à surveiller. Jamais de float sur le fil — entiers ×1000 pour les facteurs, ×100 pour rad/s et µT, ×10 pour les degrés cap.
Les 5 catégories (CAT)
V — Consigne
Commande émise par SP vers SE ou Arduino. Déclenche une action ou un changement d'état. Exemples : $V:CfgS:modeRZ:*:2# (passer en mode FIXE) · $V:CamSE:modeCam:rear:stream# (caméra — appel direct à rz_camera_manager.sh, qui délègue ensuite à Tasker en interne).
I — Info / ACK
Acquittement ou information ponctuelle. SE ou Arduino confirment réception d'une commande V, ou envoient un état non-urgent. Exemple : $I:COM:info:SE:SE_READY#.
E — Événement urgent
Événement nécessitant une réaction immédiate. Priorité absolue dans le routage — traité avant tout autre message. Exemple : $E:Urg:etat:SE:danger#.
F — Flux continu
Données périodiques de capteurs. Haute fréquence. Côté SP : alimente le contexte global uniquement, pas de décision. Exemple : $F:Gyro:dataContGyro:*:[120,-45,300]#.
A — Application Android
Commande destinée à Tasker. Routée par rz_vpiv_parser.sh vers fifo_tasker_in. Couvre Appli, Voice, TorchSE, ExprTasker. Exemple : $A:Appli:expr:*:sourire#.
⚠️ CamSE n'est pas CAT=A malgré l'implication de Tasker dans sa chaîne d'exécution. La trame reçue par SE est CAT=V/F, traitée par appel direct à rz_camera_manager.sh (pas de passage par fifo_tasker_in). C'est ce script qui délègue ensuite à Tasker en interne pour le lancement effectif de l'app — Tasker est un détail d'implémentation interne au module CamSE, pas la catégorie VPIV de la trame d'origine. Confirmé dans le code source de rz_vpiv_parser.sh (case "V"|"F" → module CamSE) et dans la Table A (modeCam/paraCam/snap classés CAT=V).
Variables clés — valeurs et signification
CfgS.modeRZ : 0=ARRET | 1=VEILLE | 2=FIXE | 3=DEPLACEMENT | 4=AUTONOME | 5=ERREUR CfgS.typePtge: 0=Ecran | 1=Vocal | 2=Joystick | 3=Laisse | 4=Laisse+Vocal CfgS.typeReseau: WifiInternetBox | Wifi4KSP | WifiSPSsI | 4K Urg.statut : cleared | active Urg.niveau : warn | danger // deux propriétés distinctes, pas une seule enum
Exemples de trames réelles
// Commandes SP→SE (CAT=V) $V:CfgS:modeRZ:*:2# // Passer en mode FIXE $V:CfgS:typePtge:*:1# // Pilotage vocal $V:Mtr:cmd:*:500,300,2# // Moteurs : v=500, omega=300, A=2 $V:CamSE:modeCam:rear:stream# // Démarrer caméra arrière (PAS CAT=A — voir note ci-dessus) // Flux capteurs SE→SP (CAT=F) $F:Sys:dataContCpu:SE:42# // CPU 42% $F:Gyro:dataContGyro:*:[120,-45,300]# // Gyro x,y,z en rad/s×100 $F:Mag:DataContMg:*:1850# // Cap 185.0° (degrés×10) // Info / ACK SE→SP (CAT=I) $I:COM:info:SE:SE_READY# // SE prêt au démarrage $I:CfgS:modeRZ:*:2# // ACK changement modeRZ // Urgence (CAT=E) $E:Urg:etat:SE:danger# // Urgence danger depuis SE // Application Android (CAT=A) $A:Appli:expr:*:sourire# // Expression sourire $A:TorchSE:etat:*:on# // Torche allumée
Cycle d'une trame — chemin complet
Chemin aller — SP → SE (commande)
①
SP — Node-RED décide
Gtion_EtatGlobal valide l'intent. Produit une commande vers CMD_FROM_BRAIN → Bus_GestionFlux.
②
Trame construite
fn_encoder_router_v3 encode : $V:CfgS:modeRZ:*:2#
③
MQTT publish SE/commande
Broker reçoit et distribue vers tous les abonnés de SE/commande.
④
rz_vpiv_parser.sh reçoit
Découpe $V:CfgS:modeRZ:*:2# → CAT=V, VAR=CfgS, PROP=modeRZ, INST=*, VAL=2.
⑤
Routage par CAT et VAR
CAT=V + VAR=CfgS → fifo_termux_in → rz_state-manager.sh.
⑥
Action exécutée
global.json mis à jour : CfgS.modeRZ = 2. ACK émis : $I:CfgS:modeRZ:*:2#
Chemin retour — SE → SP (flux capteur)
Ⓡ①
Manager capte une donnée
rz_gyro_manager.sh lit le LSM6DS3C via termux-sensor.
Ⓡ②
Trame VPIV formatée
$F:Gyro:dataContGyro:*:[120,-45,300]# — valeurs entières ×100.
Ⓡ③
Écriture dans fifo_termux_in
Règle absolue : jamais mosquitto_pub direct. FIFO uniquement.
Ⓡ④
rz_vpiv_parser publie MQTT
Lit la FIFO et publie sur SE/statut vers le broker.
Ⓡ⑤
SP reçoit et met à jour
Bus_GestionFlux : CAT=F → global.get('RZ_Gyro').dataContGyro._last = [120,-45,300].
