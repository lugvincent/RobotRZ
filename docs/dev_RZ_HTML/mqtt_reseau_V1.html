Les 4 scénarios — par ordre de priorité
1Wi-Fi maison
SE se connecte à la box domestique. Joint SP RPI directement en local sans passer par internet. Mode nominal, le plus stable et le plus rapide.

SE IP : 192.168.1.12 · SP RPI IP : 192.168.1.40 · Broker : 192.168.1.40:1883
CfgS.typeReseau = WifiInternetBox
2Wi-Fi externe (chez des connaissances)
SE se connecte à la box d'un tiers. SP RPI est toujours le maître mais accessible uniquement via internet (DuckDNS). La data consommée est celle de la box du tiers.
CfgS.typeReseau = WifiInternetBox
3Hotspot SP Smart — 4G active
Pas de Wi-Fi disponible. SE se connecte au hotspot du Xiaomi (SP Smart). SP RPI reste le maître, accessible via DuckDNS. La data consommée est celle du forfait SP Smart (Xiaomi). SP Smart sert uniquement de passerelle réseau — il ne pilote pas.
CfgS.typeReseau = Wifi4KSP
4Hotspot SP Smart — sans 4G (réseau local)
Pas de réseau, ou volonté d'économiser le forfait. SE se connecte au hotspot du Xiaomi sans activation de la 4G. SP Smart (Node-RED sur Xiaomi) devient le SP actif — il remplace SP RPI. Le broker MQTT tourne lui aussi sur le Xiaomi. Échange purement local, zéro consommation data.
CfgS.typeReseau = WifiSPSsI
⚠ En scénario 4, le broker MQTT n'est plus 192.168.1.40 — il est sur le Xiaomi. SP Smart doit donc héberger un broker Mosquitto local. La variable CfgS.typeReseau = WifiSPSsI permet à SE de savoir quel broker contacter.

Régénérer MQTT_PASS — procédure (3 emplacements)
⚠ MQTT_PASS doit être mis à jour simultanément à 3 endroits — un oubli casse la connexion broker sans message d'erreur évident côté client.
1. Mosquitto — RPi (SP RPI)
sudo mosquitto_passwd /etc/mosquitto/passwd rpibrokerUser sudo systemctl restart mosquitto # Rappel : systemctl status est paginé — taper "q" pour quitter l'affichage
2. keys.json — Doro (SE)
Mettre à jour la valeur MQTT_PASS dans ~/robotRZ-smartSE/termux/config/keys.json.
3. Node-RED — SP RPI
Nœud broker MQTT → onglet Sécurité → nouveau mot de passe → Deploy.
✅ Validation : mosquitto_pub depuis le Doro avec les variables lues depuis keys.json → succès sans erreur.
⚠ Piège : éviter les caractères spéciaux (! @ $ # %) dans le mot de passe — ils posent problème dans les variables shell bash. Préférer lettres + chiffres uniquement pour tout credential qui transite par un script.
