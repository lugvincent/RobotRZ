SP Arduino Tasker STT & Voice Réseau

SE — Smartphone Embarqué

Cerveau local mobile du robot. Bridge entre Arduino et SP. Gère capteurs, STT/TTS, caméra et applications Android. Doro Android sans SIM — IP locale 192.168.1.12.

Environnement logiciel
Termux
Linux sur Android. Exécute tous les scripts Bash et Python. Port SSH : 8022. Répertoire : ~/robotRZ-smartSE/
Tasker
Automatisation Android. Gère apps, UI, AutoVoice, TTS. Reçoit ordres via trigger.txt, envoie commandes via vpiv_out.txt.
Termux:API
Passerelle Termux↔Android. TTS via termux-tts-speak. Torche. Capteurs (termux-sensor).
IP Webcam Pro
Streaming HTTP port 8080. Démarré/arrêté par Tasker (RZ_CamStart/Stop).
AutoVoice
STT via moteur Android. v4.0.14. PocketSphinx abandonné (OpenSL ES inaccessible Android 9). Voir STT →
Connectivité
4 scénarios réseau. Priorité : Wi-Fi maison → Wi-Fi ext → Hotspot 4G → Hotspot local. Détail →

Routeur central. Écoute SE/commande via MQTT en continu.
CAT=E · Urg · etat · danger→safety_stop.sh (priorité absolue)
CAT=V/F · CamSE→appel direct rz_camera_manager.sh ($PROP $VAL $INST) — qui délègue ensuite à Tasker en interne
CAT=V/F · CfgS et autres→fifo_termux_in → state-manager

rz_state-manager.shv1.5
Gardien de l'état global. Lit fifo_termux_in. Met à jour global.json. Émet les ACK VPIV. Nouveautés v1.5 :
• sync_to_tasker() — copie global.json vers /sdcard/Tasker/RobotRZ/global.json après chaque écriture. Requis par RZ_OuvreEtat. Appelée à 4 endroits.
• calculate_stt_context() — calcule le contexte STT (Inactif/Cmde/Conv/Mixte) et écrit trigger.txt avec champ ts (timestamp). Appelée après chaque changement de modeRZ ou typePtge.
• Cas STT dans le switch : modeSTT=OFF → STT.context=Inactif · modeSTT=KWS → recalcul contexte · paraSTT={...} → écrit dans STT.paraSTT
// trigger.txt — écrit par calculate_stt_context() après sync_to_tasker() printf '{"task":"RZ_STT_Context","param":"%s","ts":"%s"}' "$context" "$(date +%s)" > "/sdcard/Tasker/RobotRZ/trigger.txt" // ts obligatoire — garantit la détection même si le contexte est identique

Versions des fichiers de configuration — état 22 juin 2026
⚠️ Point de vigilance — avant d'ajouter un manager à rz_start.sh : vérifier s'il est conçu comme daemon ou one-shot. Certains scripts SE (rz_camera_manager.sh, rz_torch_manager.sh, probablement d'autres à vérifier) sont des one-shot invoqués à la demande par rz_vpiv_parser.sh avec arguments (PROP VAL INST), pas des daemons à lancer en arrière-plan sans argument. Le confondre produit un exit 1 silencieux sans casse fonctionnelle majeure, mais pollue les logs et fausse cmd_status(). Le commentaire d'en-tête du script ("appelé à la demande, one-shot, pas daemon") est le signal à chercher avant toute intégration.
⚠️ Point de vigilance — vérifier le démarrage automatique d'un daemon attendu : avant de supposer qu'une fonctionnalité ne marche pas pour une raison logique, vérifier qu'elle est bien lancée par un mécanisme automatique (rz_start.sh ou tâche Tasker de boot). rz_appli_manager.sh n'a jamais été dans rz_start.sh ni dans RZ_Init_Tasker.tsk.xml depuis la création du projet — aucune commande Appli n'a donc jamais pu fonctionner, sans symptôme visible. pgrep -f <nom_script> est le réflexe de vérification simple avant tout diagnostic plus poussé.
