⚠️ Point bloquant identifié en lisant le code (pas une déduction) : dans rz_stt_handler.sh v2.6, le case "$TRAITEMENT" in ... esac ne contient que SIMPLE|LOCAL et COMPLEXE. Les commandes traitement:"PLAN" du catalogue (MTR_TURN_ANGLE, MTR_SPEED_SET, MTR_ADVANCE_DIST) tombent dans le vide : ni trame VPIV, ni retour TTS. Voir détail dans l'onglet "Détail SE".
Exemple de trajet complet — même variable, deux formats de trame
Une commande vocale reconnue (ex. CFG_VEILLE) devient côté SE la capsule $A:STT:intent:*:{V:CfgS:modeRZ:*:1}#, publiée sur SE/statut. Côté SP, fn_stt_intent_router la déballe et ne conserve que la trame interne : msg.vpiv = {cat:'V', var:'CfgS', prop:'modeRZ', inst:'*', val:'1'} — c'est cette forme "nue", identique à celle d'une commande dashboard, qui entre dans Gtion_EtatGlobal_V1. Le marqueur msg.origine="STT" est la seule trace qu'il s'agissait d'une commande vocale.
