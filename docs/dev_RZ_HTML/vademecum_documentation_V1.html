RobotRZ Vade-mecum de la documentation V1 — 20 octobre 2026

Où est quoi, et qu'est-ce qui fait foi

Cette page répond à la seule question qui compte quand on revient au projet après une pause : dans quel des quatre emplacements chercher un document, lequel fait autorité en cas d'écart, et où ranger ce qu'on produit aujourd'hui.

1 — Les quatre emplacements

La documentation du projet vit à quatre endroits, et ce n'est pas un défaut : chacun a une raison d'être distincte. Les confondre est en revanche la source d'erreur la plus courante.

① Le dossier documentaire local
Documents\ProjetRZ\AA-Doc-horsGit\ — hors dépôt Git, volontairement
Votre atelier. Notes de travail, documents bureautiques, tableurs, bilans de séance, schémas sources. Classé par lettres, voir la section 3.

Pourquoi hors dépôt : ce sont des documents de travail, souvent volumineux, qui n'ont pas leur place dans un dépôt de code — et surtout, ce dossier contient vos identifiants. Le dépôt est public.
② Le site de documentation
docs/dev_RZ_HTML/ dans le dépôt — ouvrir index.html dans un navigateur
La documentation de référence, celle qu'on consulte pour comprendre comment le robot fonctionne : protocole VPIV, tables, modules, réseau, sécurité, et le dossier technique d'ensemble. Elle est versionnée, donc son histoire est consultable.

Ce qui n'y entre pas : les bilans de séance, qui restent délibérément locaux dans M - Bilans de seance.
③ La synthèse d'état
Project Knowledge : claude/synthese_etat_oct2026.md — archive : docs/synthese_etat.md
L'état réel du projet à un instant donné : ce qui marche, ce qui est cassé, ce qui reste à faire en lots dimensionnés, les invariants à ne jamais enfreindre. C'est le document à lire en premier quand on reprend après une pause, et celui que lisent les conversations du projet.

Il existe en deux copies dont les rôles diffèrent — voir la section 2.
④ Le dépôt Git
github.com/lugvincent/RobotRZ — public
Le code : scripts SE, firmware Arduino, tâches Tasker, exports des flux Node-RED, et le site de documentation lui-même. Tout ce qui s'exécute ou se déploie.
2 — Qui fait foi en cas d'écart

Quand deux copies divergent, une seule a raison. Ce tableau évite d'avoir à le deviner.

SujetFait foiPourquoi
Flux Node-RED flows.json dans l'éditeur Le robot tourne avec ce qui est dans l'éditeur, pas avec le fichier du dépôt. On modifie, on déploie, on teste, puis on exporte. Jamais l'inverse.
Code des nœuds function flows.json node-red/functions/ n'est qu'une copie lisible, pour que Git montre des différences compréhensibles. Node-RED ne lit jamais ce dossier.
État du projet La copie du Project Knowledge C'est la seule que les conversations mettent à jour. Celle du dépôt est une archive datée, qui peut avoir une version de retard — le numéro en tête permet de le vérifier.
Variables VPIV Table A Référence normative du développement. Jamais chargée à l'exécution : elle sert à concevoir.
Valeurs à l'exécution global.RZ_<VAR> enrichedVars ne sert qu'à l'amorçage, et ne se modifie que par ui_VarG.
Tables B, C, D Le Raspberry Pi Le PC est l'atelier de conception, le RPi porte l'autorité d'exécution. Chaque sous-système garde une copie locale pour démarrer seul ; SP l'écrase après SE_READY.
3 — Le classement du dossier local
La règle tient en une phrase : le thème décide du dossier, l'âge décide de la place à l'intérieur de ce dossier. Une seule question à se poser, une seule réponse possible.

Les versions dépassées ne partent pas dans un dossier séparé : elles descendent dans le sous-dossier old\ de leur propre lettre, au plus près de ce qu'elles complètent. C'est ce qui a remplacé l'ancien G - Old.

A
Architecture, règles, tables — la conception d'ensemble et les tables de référence
B
SP — Node-RED : le superviseur, ses flux, ses interfaces
C
SE — Termux et Tasker : le smartphone embarqué
D
Arduino — Mega et UNO, firmware et bibliothèques
E
Exception assumée. Sas d'échange ponctuel, fait pour être vidé. Ce qui y séjourne n'est rangé nulle part — c'est le signal qu'il faut s'en occuper.
F
Exception assumée. Le travail du moment, rassemblé en un endroit pour le retrouver sans parcourir les autres lettres. Se vide quand le chantier se termine.
H
Outils — installation, scripts d'aide, utilitaires
I
Archive — sujets clos, conservés pour mémoire, plus aucun usage courant
J
Électronique et câblage — schémas, brochages, circuits. Traversent les générations du robot, d'où leur lettre propre.
K
Documents utilisateurs — notices, guides, présentations destinées à d'autres qu'au développeur
L
RZ-v1 sur RPi4 — la génération antérieure du robot, encore en service. Ce n'est ni du vieux ni de l'archive : tant qu'une machine tourne, sa documentation est opérationnelle.
M
Bilans de séance — le journal de travail, par date. Restent locaux, n'entrent pas dans le site.
Z
Secret. Clés, identifiants, codes. Voir la section 5.

CODE\ reste à part, à la racine : ce sont des copies de travail de code, pas de la documentation.

Pourquoi cette structure. Jusqu'au 20 octobre 2026, deux axes de classement coexistaient — un thématique et un temporel — et le second dupliquait le premier dans ses sous-dossiers. Chaque document avait donc deux emplacements également légitimes, et face à deux réponses valables on ne tranche pas : d'où les fichiers posés à la racine et le dossier « non classé ». Le désordre n'était pas de la négligence, c'était la conséquence mécanique d'une structure ambiguë.

Le geste de fin de séance Node-RED. Node-RED ne versionne rien tout seul : un export manuel est la seule sauvegarde qui existe. 5 — La règle de sécurité
Le dépôt est public. Tout fichier non exclu par le .gitignore part en ligne au premier git add .. Le dossier AA-Doc-horsGit\ est exclu dans son intégralité, et doit le rester.
Si vous renommez ce dossier, ajoutez le nouveau nom au .gitignore dans le même geste. L'exclusion porte sur le nom. Un renommage la rend caduque, et le dossier — clés comprises — redevient publiable sans que rien ne vous avertisse. Le piège a été rencontré le 20 octobre 2026 ; les deux noms, l'ancien et le nouveau, figurent désormais dans le fichier.

Trois règles de conduite, sans exception :

Jamais git remote -vdans une conversation ou un log partagé — le jeton du Doro y apparaît en clair dans l'URL. Passer par set_git_remote.sh.
Jamais une clé en clairdans un message, un ticket, une capture d'écran.
Vérifier par la longueurcharger un identifiant dans une variable shell et contrôler ${#TOKEN}, jamais en affichant sa valeur.
Une amélioration qui reste à faire. Les identifiants sont aujourd'hui dans un fichier texte en clair. L'exclusion Git les protège d'une publication accidentelle, et de rien d'autre : toute personne ou tout programme ayant accès à la session Windows les lit. Un gestionnaire de mots de passe local et chiffré — KeePassXC, gratuit, un seul fichier — offrirait une vraie protection pour le même confort d'usage.
6 — Je ne trouve pas un document

Dans l'ordre, et ça couvre à peu près tout :

Chercher par le thème
La lettre du sujet, puis son old\. C'est la règle : le thème décide du dossier.
Chercher par la date
Si c'était un travail de séance, M - Bilans de seance est classé chronologiquement.
Chercher dans le dépôt
Si c'est de la référence ou du code : le site HTML, ou l'historique Git avec git log --all -- "*motcle*".
Chercher dans le sas
E contient ce qui n'a pas encore été rangé. S'il grossit, c'est le signal qu'il faut y passer une demi-heure.
