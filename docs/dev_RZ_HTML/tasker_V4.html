Tasker — Couche Android V4

Gère les apps Android et l'UI du robot. Pipeline bidirectionnel : reçoit VPIV CAT=A via trigger.txt, envoie commandes via vpiv_out.txt → SP. Tasker 6.6.20 sur Doro.

Pipelines — bidirectionnels (V4)
SP → SE → Tasker (commandes reçues)
SP publie VPIV CAT=A sur SE/commande→$A:TorchSE:etat:*:on#
rz_vpiv_parser.sh détecte CAT=A→fifo_tasker_in → rz_tasker_bridge.sh
rz_tasker_bridge.sh→écrit trigger.txt via printf (avec ts)
Profil Fichier_ModifieParSE surveille trigger.txt→RZ_Dispatch
RZ_Dispatch JavaScriplet→parse JSON → %RZtask / %RZparam → Effectuer tâche
ℹ️ Cas particulier CamSE : $V/F:CamSE:modeCam:rear:stream# n'est pas CAT=A — appel direct rz_camera_manager.sh par rz_vpiv_parser.sh, qui délègue ensuite à Tasker en interne (RZ_CamStart/Stop) via rz_tasker_bridge.sh. Voir détail dans la section RZ_CamStart ci-dessous.
Tasker → SE → SP (commandes envoyées) Nouveau V3
Bouton menu / action Tasker→writeFile() JavaScriplet → vpiv_out.txt
rz_tasker_out.sh (inotifywait)→détecte modification vpiv_out.txt
mosquitto_pub SE/statut→Node-RED SP → parseVPIV → Gtion_EtatGlobal

Règles critiques
Variables locales %minuscules — globales %AuMoinsUneMajuscule
JavaScriplet : global('NomSansPourcent') — JAMAIS de % dans global()
JAMAIS return hors d'une fonction en JavaScriplet → crash Tasker silencieux
trigger.txt écrit avec printf + champ ts (timestamp) — garantit détection même si contenu identique
Séquence scène OBLIGATOIRE : Détruire (49) → Afficher (47) → Wait 500ms → Définir éléments (51)
Code 547 : arg5=3 (global) et arg6=1 — les deux obligatoires
JAMAIS de second contexte variable sur un profil AutoVoice — bloque le déclenchement
Opérateur "ou" dans conditions Tasker : / — pas |
%avcomm et %avcommnofilter disponibles UNIQUEMENT dans la tâche directe du profil — ne traversent pas "Effectuer la tâche"
Scripts Termux:Tasker dans ~/.termux/tasker/ — symlinks requis, chmod +x obligatoire après tout remplacement de fichier
VARIABLE_REPLACE_KEYS (import XML) — quand une action Termux:Tasker est importée via XML, ce champ peut être absent → les variables Tasker arrivent comme chaînes littérales non résolues (ex: %PhraseRZRetire arrive comme la chaîne "%PhraseRZRetire"). Toujours re-saisir manuellement les arguments dans Tasker UI après tout import XML d'une action Termux:Tasker.
Git Tasker XML — les XML dans tasker/tasks/ et tasker/profiles/ ne se mettent pas à jour automatiquement. Après modification dans Tasker UI → exporter depuis Tasker → cp /storage/emulated/0/Tasker/tasks/*.tsk.xml ~/robotRZ-smartSE/tasker/tasks/ → commit.
