STT & Voice — Module vocal

Reconnaissance vocale (STT) et synthèse vocale (TTS) du robot. Architecture "Option B" : routage Cmde/Conv/Mixte décidé côté SE (bridge), Tasker se limite à transmettre. AutoVoice — PocketSphinx abandonné (Android 9).

🎯
Architecture STT Option B validée et testée — 21 juin 2026
Routage complet Cmde / Conv / Mixte fonctionnel dans rz_autovoice_bridge.sh v3.0. Les 3 contextes testés avec succès. Gemini opérationnel (gemini-2.5-flash). Tâche RZ_IA_Conv créée et testée.
Décision architecturale — PocketSphinx abandonné
PocketSphinx définitivement abandonné sur Doro / Android 9.
Cause racine : OpenSL ES inaccessible depuis un processus Termux non privilégié. Conservé dans Git pour un futur usage sur RPI ou appareil avec micro USB.
AutoVoice retenu comme moteur STT. Accès micro natif Android fiable. Mode commandes : offline (moteur Android). Mode conversation libre (Gemini) : nécessite internet.
Architecture Option B — un seul mot-clé "rz"
Principe : le bridge SE décide, Tasker transmet
Contrairement à l'architecture précédente (Tasker décidait via %RZsttContext), c'est maintenant rz_autovoice_bridge.sh qui lit STT.context dans global.json et décide du routage. Tasker (Rz_Traite_Ecoute) a été radicalement simplifié : il ne fait plus que transmettre la phrase au bridge.

Raffinement sécurité — VEILLE + mouvement
Si modeRZ=1 (VEILLE) ET mouvement détecté (Mtr.state.L≠0 ou R≠0) → STT.context forcé à Cmde au lieu de Mixte. Protège le seul cas réellement à risque : un déplacement initié pendant que modeRZ reste VEILLE.
🔴 Robot.speed N'EXISTE PAS dans Table A. Variable découverte inexistante — remplacée par Mtr.state (CAT=I, format "L,R,A"), seule donnée VPIV réelle pour détecter un mouvement moteur.
⚠ Câblage Node-RED SP en attente — SP doit relayer la trame Mtr.state reçue d'Arduino vers SE ($I:Mtr:state:*:L,R,A# sur SE/commande) pour que la protection VEILLE+mouvement fonctionne réellement. Code SE prêt, valeur par défaut sûre 0,0,0 en son absence.
Valeur "Conv" réservée à un déclenchement explicite. Aucun modeRZ ne produit Conv automatiquement — elle est activée uniquement via Appli.IA_Conv (tâche Tasker RZ_IA_Conv), indépendamment du modeRZ courant.

Infrastructure Termux:Tasker — symlinks définitivement interdits
🔴 RÈGLE CRITIQUE — après reboot Android, Termux:Tasker refuse les symlinks ("Non-regular file found at executable file path"). tasker/rz_autovoice_bridge.sh et tasker/rz_start.sh étaient des symlinks Windows-style créés par VS Code → remplacés définitivement par des copies réelles (rm + cp + chmod +x).
